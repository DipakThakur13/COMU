# Benchmark run: B1

Model `nvidia/nemotron-3.5-lightning-30b-a3b` via nvidia. Commit `85b0a1c`.
1 repetitions per fixture, 5 runs measured, started 2026-09-24T07:59:07.809Z. 10 more were ended by the provider and are not counted anywhere below; see "Not measured".

**Limitations.**

- Not comparable with B0, and mostly not measured. 10 of the 15 cells were ended by NVIDIA gateway 504s, each on a request of about 302 seconds (12 of the 15 cells had at least one request over 295 s), so B1 measured 5 cells, not 15. Its median model request latency per cell was 108 s across all 15 cells and 85 s across the 5 measured ones; B0 recorded no request latency to set beside it. On the one measure both runs carry, wall clock per successful model request, B1's median was 164 s (118 s on the measured cells) against B0's 71 s. B0's 71 s is itself a blend of two gateways: 12 cells measured on 2026-09-20 at a median of 58 s, and 3 on 2026-09-23 at 105 to 257 s. B1 ran on a slower gateway than the one B0 mostly measured, so every time budget bit sooner: the 25-minute execution limit ended t2-ts-retry, t3-ts-extract and t4-py-parser. No difference in a time-limited cell can be attributed to the engine.
- Per cell, beside B0, for the 5 measured cells (wall clock per successful request, B0 then B1; B1's measured request latency in brackets): t1-py-interval 75 s then 87 s (70 s); t2-ts-retry 103 s then 173 s (176 s); t3-ts-extract 257 s then 119 s (86 s); t4-py-parser 71 s then 104 s (85 s); t4-ts-async 197 s then 118 s (82 s). t3-ts-extract and t4-ts-async were among B0's three cells measured on the degraded 2026-09-23 gateway, which is why B1 looks faster there; against B0's 2026-09-20 cells B1 is slower throughout.
- The launch gate passed with probes of 75.8 s, 70.4 s and one that gave no answer within 142 s (median 75.8 s, threshold 142 s). It compares a one-token request with B0's wall clock per request, which includes tool and test time, so it is lenient: a one-token request that takes 70 s is already a slow gateway. It did not stop this launch, and the gateway degraded further during the run.
- T7: the two TypeScript cells changed fixture as well as engine since B0 (commit 3d973ef made them typecheck in their untouched state), so only t7-py-architecture isolates the engine within T7. In B1 all three T7 cells were ended by the provider, so B1 says nothing about T7.
- False completions were zero at B0 rep 1, so the zero here is not evidence of anything, least of all over 5 measured cells.
- One repetition: this is diagnostic, not statistical. A single cell moving says nothing about the engine by the rules this benchmark committed to before any result existed.
- t1-py-interval ended VERIFICATION_UNAVAILABLE: COMU's verification found no typecheck or test command for the Python fixture and finished in 7 ms, although the agent had run pytest successfully earlier in the same task. In B0 its work was correct (a false failure); here the agent had identified the fix but it was not in place when the task ended. That is an engine finding, not a provider effect.
- t1-ts-pagination's work was correct when a later request died on a 504. It is excluded like every other cell the provider ended: a run the provider ended is not scored, whichever way the grader came out.
- Concurrency 2 throughout, as in B1's first launch. B0's rep 1 did not run at one concurrency: several 2026-09-20 cells started three or four at a time, before concurrency was recorded per record, and the 2026-09-23 cells ran at 2.
- Engine as of d6c8122 (Stage 0); the launch commit 0038ff3 differs from it only in the benchmark instrument. The journal also holds two records from B1's first launch on 2026-09-23, which died at 2 of 15; both were provider kills and were measured again.

## Reading a delta against this run

A change smaller than the run to run spread is no detected change. Specifically:

- A fixture moving by one repetition out of 1 is noise, not a result.
- A fixture moving by two or more is a signal for that fixture.
- A suite level claim needs two or more fixtures moving by two or more in the same direction.
- A continuous metric has moved only when the two runs' ranges do not overlap.
- A failure class has moved only when its count changes by more than the number of fixtures that moved.
